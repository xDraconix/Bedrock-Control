# Bedrock Control PRO v2.6.0 Stable

## Neu: signierte Updates für Weboberfläche und Systemkomponenten

Der Update-Manager erweitert den bisherigen signierten Web-Datei-Austausch um einen **eng begrenzten, geprüften Systemkomponenten-Updatepfad**. Damit können spätere signierte Releases auch unterstützte Root-Hilfsprogramme, die eigene Update-systemd-Unit, sudoers sowie ausgewählte Apache-, PHP- und tmpfiles-Konfigurationen erneuern.

- **Signatur und Integrität:** Ed25519-Signatur, SHA-256 und ZIP-Struktur werden vor Änderungen gegen den bereits lokal installierten vertrauenswürdigen Public Key geprüft.
- **Dateifreigabeliste:** Nur fest definierte Bedrock-Control-Dateien dürfen ausgetauscht werden. Beliebige Shell-Skripte aus einem ZIP oder ein darin enthaltenes `install.sh` werden nicht ausgeführt.
- **Vorprüfungen:** PHP- und Skript-Syntax, sudoers und Apache-Konfiguration werden geprüft, bevor die Systemdateien aktualisiert werden.
- **Snapshot und Rücksprung:** Vor dem Austausch erstellt das Panel einen Integritäts-geprüften Snapshot. Bei kontrolliertem Fehler stellt es die vorherigen Dateien samt Rechten und Besitzern wieder her; neu angelegte Update-Dateien werden für die Bereinigung erfasst.
- **Dienstprüfung:** Nach dem Austausch werden PHP, sudoers, Apache, das Panel-HTTP-Interface und der Minecraft-Dienststatus kontrolliert.

**Minecraft bleibt außerhalb des Updateumfangs:** Welten, `server.properties`, `mcbedrock.service` und Minecraft-Start-/Stoppskripte gehören nicht zum signierten Panel-Systemupdate. Der Updater führt keinen beabsichtigten Neustart von Minecraft aus. Der bereits installierte öffentliche Vertrauensschlüssel bleibt unverändert.

## Wichtige Upgrade-Anleitung: v2.5.5 → v2.6.0

**Einmalig muss v2.6.0 mit dem Installer installiert werden.** Der bestehende v2.5.5-Web-Updater besitzt noch keine Berechtigung bzw. Logik, um die neuen Root-Hilfsprogramme zu installieren. Ein reines Webpanel-Update von v2.5.5 ist daher **keine vollständige v2.6.0-Installation**.

1. Vorher einen Proxmox-Snapshot bzw. ein externes Backup erstellen.
2. Das **offizielle signierte v2.6.0-Release** herunterladen, Ed25519-Signatur und SHA-256 mit dem bereits vertrauenswürdigen Schlüssel verifizieren.
3. Das verifizierte Installations-ZIP entpacken und als root darin `bash install.sh` ausführen. Den Schlüssel aus dem Release **nicht** ungeprüft als neue Vertrauensbasis übernehmen.
4. Version, System-Planer, Apache, sudoers und Minecraft prüfen.

Beispiel nach sicherem Herunterladen und Verifizieren:

```bash
unzip Bedrock-Control-PRO-v2.6.0-Release.zip
cd bedrock-control-pro-2.6.0-installer
bash install.sh

cat /opt/bedrock-control-pro/VERSION
test -x /usr/local/bin/bedrock-panel-system-plan
visudo -cf /etc/sudoers.d/bedrock-control-pro
apache2ctl configtest
systemctl is-active apache2 mcbedrock.service
```

Die **anschließend** installierte v2.6.0-Update-Engine kann bei neueren signierten Releases die freigegebenen Systemdateien über den Ein-Klick-Updater verwalten. Systemdateien außerhalb dieser Allowlist benötigen weiterhin einen bewussten Installationsschritt.

## Tests und Freigabestatus

Getestet auf dem isolierten Debian-13-Container `Minecraft-Test-2`:

- Installierter v2.6.0-Planer erkennt 27 zulässige Systemkomponenten.
- Signiertes v2.6.1-Testupdate aktualisierte nachweislich ein Root-Hilfsprogramm, Apache und Minecraft blieben aktiv.
- Signiertes v2.6.2-Fehlerpaket löste HTTP 503 aus; automatischer Rollback auf v2.6.1.
- Absichtlich unterbrochene signierte Update-Transaktion beim dritten Systemkomponententausch löste Rollback auf v2.6.1 aus.
- Vergleich des Recovery-Snapshots: 40 geprüfte Dateien, keine Inhalts-/Berechtigungs-/Eigentümerabweichungen.
- Manipulierte ZIP-Datei und manipulierte Ed25519-Signatur wurden vor dem Austausch zurückgewiesen.
- Isolierte Tests prüften die Entfernung neu angelegter Systemdateien und die Zurückweisung von Symlinks.

**Abdeckung:** Das Entfernen einer während eines **realen** signierten Updates neu eingeführten Systemdatei wurde nur isoliert, nicht Ende-zu-Ende auf einem laufenden Container getestet. Die Freigabe ersetzt keine Proxmox-/Weltbackups.

## Herausgeber

Ein offizielles Release besteht aus genau drei Assets:

- `Bedrock-Control-PRO-v2.6.0-Release.zip`
- `Bedrock-Control-PRO-v2.6.0-Release.zip.manifest`
- `Bedrock-Control-PRO-v2.6.0-Release.zip.manifest.sig`

Erstellung/Signatur ausschließlich auf dem vertrauenswürdigen Signierrechner mit `release-tools/prepare-signed-release.sh` und lokalem privaten Ed25519-Schlüssel. Den **privaten Schlüssel niemals hochladen**. Git-Branch `main` muss vor dem Signieren auf v2.6.0 zeigen. Erst nach Merge, Freigabe und erfolgreicher Signaturprüfung veröffentlichen.
